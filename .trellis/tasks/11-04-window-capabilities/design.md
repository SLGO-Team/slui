# 设计：按窗口拆分 capability

## 机制

- `src-tauri/app-commands.rs`：全部 31 个自定义命令的列表，`build.rs` 用 `include!` 读入并交给
  `tauri_build::AppManifest::new().commands(...)`。有了 app manifest，Tauri 2.12 对每个 app 命令都做 ACL
  检查（`webview/mod.rs`：`plugin_command.is_some() || has_app_acl_manifest || !is_local`），没被授予就拒绝。
- tauri-build 为每个命令生成 `allow-<命令>` / `deny-<命令>`（下划线换成连字符），写到
  `src-tauri/permissions/autogenerated/`（构建产物，gitignore）。
- capability 拆成三个文件：`shared.json`（两个窗口）、`home.json`、`overlay.json`。
  `core:default` 不再整体给出（它含 tray/menu/image 创建、窗口查询等两个窗口都用不到的命令），
  只给实际用到的：两个窗口 `core:event:default`；home 的标题栏（start-dragging、
  internal-toggle-maximize、minimize、close）和项目链接（opener，限定 URL）；
  `core:webview:allow-internal-toggle-devtools` 只在带 devtools 的调试构建有作用。

## 命令归属（按前端实际调用核对）

- 两个窗口：`log_overlay_event`（页面错误日志）、`list_theme_pack_files`（main.tsx）、`load_settings`、
  `get_overlay_state`、`set_overlay_enabled`（home 开关；overlay 自动启用）、`get_game_running`、
  `get_game_conditions`、`get_update_state`。
- 只给 home：`save_settings`、`reveal_log_file`、`relaunch_elevated`、`get_steam_profile`、
  `updater_start` / `updater_check_now` / `updater_install`。
- 只给 overlay：`set_overlay_interactive`、`set_overlay_keyboard_focus`、`set_overlay_session_live`、
  `set_hotkeys`、`set_scoreboard_capture`、`get_overlay_visibility`、`get_game_foreground`、
  `get_current_steam_identity`、`game_log_size` / `game_log_read`、`set_backdrop_*`、
  `get_backdrop_available`、`sidecar_open` / `send` / `close`。

## 纵深防御与测试

- `relaunch_elevated` 注入 `tauri::Webview`，label 不是 home 就返回错误并写 diag。
- `src/command_acl_tests.rs`：manifest 与 `generate_handler!` 完全一致；每个命令至少授予一个窗口；
  capability 里没有不存在的命令；六个特权命令只给 home。
