# 小地图 CS2 对齐：SLUI 侧机制与外观

## Goal

只改 SLUI（不动插件和协议），把雷达的图标缩放、动态缩放、钥匙卡安放表现、边框、地点名、出现方式对齐 CS2，并删掉
CS2 没有的状态文字。父任务：`11-17-minimap-cs2-parity`（编号 A–E 见父任务 PRD）。

依据：`research/cs2-radar-client-re.md`（用户已同意对其本机 CS2 `client.dll` 做反汇编）以及 Panorama
`hudradar.xml` / `hudradar.css`（2026-11-16 提取）。

## Requirements

### R1 图标随雷达缩放变化（A1）

- 玩家标记整体按 `iconScale = 0.6 + (1.25 − 0.6) × 当前缩放` 缩放。其中 0.6 是 `cl_radar_icon_scale_min` 的默认值，
  不开放设置；当前缩放是实际生效的值（动态缩放或切换缩放生效时用对应的值）。全图（overview）也按当前相机
  比例计算，结果限制在 [0, 1]。
- 被缩放的是 CS2 `PlayerIcons` 里的全部内容：点、敌人菱形、朝向尖、视野扇形、死亡 X、幽灵 ?、边缘箭头。
- 基准尺寸改为 CS2 原生尺寸：队友 11、敌人 13、边缘箭头 22、死亡 19、幽灵 9×15、视野扇形 128×64。朝向尖和点的比例
  保持现状。在 0.25 缩放时画出来大约等于现在的大小（0.7625 对比现在约 0.73）。
- 钥匙卡、地上的圆环、炸弹点在 CS2 里不属于 `PlayerIcons`，先按「不缩放」处理；实现时要确认 CS2 是否在别处对它们
  用了同一个比例（implement.md 第 1 步）。

### R2 两个区域视为同一层（A2）

办公区和重收容区在同一平面上，相当于 CS2 的一层：删除 `.minimap-map__room[data-active="false"]` 的 0.82 调暗，
两区始终一样显示。不做区域淡入淡出。

### R3 动态缩放按 CS2 原版算法（A5）

开关、默认值（关闭）、只在聚焦时生效、看全图时不生效，这些都保持不变。算法替换为原版：

- 纳入对象是所有正在画的元素：活着的标记（插值后的位置）、正在淡出的幽灵 ? 和死亡 X、正在显示的钥匙卡。不按区域
  筛选，不含炸弹点。
- 目标距离 = 这些元素到视点的最大水平距离（x, z）。没有元素时为 0。
- 平滑距离 D：首次直接等于目标；目标 ≥ D 时立即跟上（扩大视野没有延迟）并清掉收缩计时；目标 < D 时，从第一次
  出现开始等 4 s，然后以每秒最多 520 个 Source 单位（按 1 单位 = 0.0254 m 换算为 13.208 m/s）向目标收缩。
- 缩放 = 让距离 D 落在视口半径 95% 的比例，限制在 [0.25, 选定比例]。圆形和方形都用半径，与 CS2 一致。
- 身份变化（视点、阵营、形状、朝向、居中、选定比例）或时钟倒退时重置。视点跨区域不算变化，因为两区是同一层。
- 只在圆形雷达上生效：CS2 在执行动态缩放前会先检查是否为圆形雷达（实现时发现）。
- 贴边位置改为半径的 98%：CS2 的 `[0x218] = (尺寸 × 0.98 × 0.5)²`（实现时发现）。原来的 12px 内缩大约是 90%，按 95%
  框进来的最远元素反而会被画成边缘箭头。标记层不再按圆形裁剪：CS2 只按面板 `rect(4px, 295px, 295px, 4px)` 裁剪，
  所以边缘箭头可以伸出圆框（录像里也是这样）。全图框选仍保留 SLUI 自己的 12px 内缩。

### R4 钥匙卡安放表现（B6）

- 安放后，钥匙卡图标加上 CS2 `PlantedBombAnimateRed` 的红色光晕脉冲：0.65 s 循环，
  阴影依次为 1px `#71060666` → 2px `#af0707AA` → 3px `#d50808EE` → 2px → 1px。
- 安放后同时显示地上圈（80px `#880000`）和安放圈（51px `#D10000`），与 CS2 的位掩码一致；之前只画安放圈。
- 没有队伍的观察者看到的钥匙卡，无论在地上还是在携带者身上，都是 CS2 默认的橙色 `#ff9b25`（之前是白色或携带者
  颜色）。己方仍是白色或携带者的槽位色，对方仍是红色。
- 不做 24px 的闪烁安放图标：CS2 从来不显示它。

### R5 安放后雷达边框闪红（B7）

发电机过载倒计时进行中（HUD `clockMode === "generator"`，相当于 CS2 的炸弹已安放且未拆除）时，圆形雷达的
边框按 CS2 `RadarBombPlantPulse` 变红并闪烁：0.65 s 线性循环，透明度 0.1 → 0.6 → 0.8 → 0.6 → 0.1。倒计时结束后
恢复原来的边框。方形雷达没有边框（R6），所以不闪。

### R6 方形雷达不画边框（C8）

CS2 的 `#Radar__Square--Border` 是 `visibility: collapse`。方形时不画 1px 边框；圆形边框不变。

### R7 地点名（C10）

按 CS2 `#DashboardLabel` 的样式：22px、Stratum2 medium、居中，宽度等于雷达面板（300px），颜色是 HUD 色
（SLGO 队伍色）。CS2 用加色混合，这在页面里做不到；实现时对照实机截图量一下字高和颜色，近似实现，并把截图位置
写进实现记录。

### R8 出现时淡入（C11）

雷达出现时（连接到服务器实例后挂载）透明度在 0.1 s 内线性从 0 到 1，对应 CS2 `.hud-radar` 的过渡。

### R9 删除 SLUI 自有文字（E17）

删除雷达下方的状态行（「实时 / 等待同步 / 位置已过期 …」和「队伍视野」）、雷达里没有地图时居中显示的状态文字，以及
没有地方使用的 `zoneLabel`。`availability` 仍保留在 `data-availability` 和诊断里，供测试和排查用。地点名不受影响。

## Acceptance Criteria

- [ ] A1：在 mapScale 0.25 / 0.7 / 1，以及动态缩放把比例压到 0.25 时，标记的渲染尺寸分别等于基准 × 0.7625 / 1.055 /
      1.25 / 0.7625。由 model 测试和视觉审计测量验证。
- [ ] A2：两个区域的房间透明度一样，不存在 `data-active="false"` 的调暗样式。
- [ ] A5：model 测试覆盖：目标变大立即生效；目标变小先保持 4 s，然后按 13.208 m/s 收缩；最远元素落在 95% 半径；
      结果限制在 [0.25, 选定比例]；不按区域筛选；淡出中的标记和钥匙卡也会被纳入；identity 变化时重置。
- [ ] B6：mock `?minimapKeycard=planted` 显示两个圈和红色光晕；团队外观察者看到橙色卡片。视觉审计断言这三点。
- [ ] B7：发电机倒计时期间，圆形边框闪红（审计采样能看到透明度变化）；倒计时结束后边框恢复；方形时没有边框。
- [ ] C8：方形雷达没有边框像素（视觉审计）。
- [ ] C10：地点名 22px，颜色是队伍色；附一张和实机截图的并排对比。
- [ ] C11：挂载后 0.1 s 内透明度从 0 到 1。
- [ ] E17：不存在 `.minimap-radar__status` 和 `.minimap-radar__empty`；断线、过期、无效时雷达区域里没有文字。
- [ ] `npm test`、`npm run lint`、`npm run build:local`、`npm run minimap-visual-audit` 通过；`minimap.md` 已同步更新。
- [ ] 用户看过 mock 截图（视觉类 PR），实机检查留给发版前。
