# SLUI 实时小地图

## Goal

在游戏内提供左上角常驻雷达，按地图种子重建办公区和重收容区，让玩家在生存和死亡后都能获得服务端授权的队伍共享视野。

## Background

- 2026-09-07 已完成用户范围确认；本任务继续沿用原小地图子任务，不另建重复任务。
- 实施前 `src/features/minimap/model.ts` 只有可见性枚举过滤和 XZ 投影；当前客户端已实现并挂载，验收证据见 `research/implementation-verification.md`。
- 正式主界面与设置由已获准创建的 `09-07-app-home-settings` 承担，实施顺序为先小地图、后主界面。

## Requirements

- 2026-09-11 实机对照与配置增量：以用户提供的 `research/reference-cs2/radar-custom.png` 及配套 `radar-settings-custom.png` 为一组自定义设置下的视觉基准，不将其数值认作 CS2 默认配置。本轮完成雷达效果与可配置接口，正式设置页面、本机保存及跨窗口同步仍由 `09-07-app-home-settings` 后续交付。
- 配置覆盖保持玩家居中、旋转、地图与背景融合、背景模糊、背景透明度、HUD 大小、地图缩放、独立切换缩放、计分板方形、强制方形与动态缩放；切换缩放动作和计分板显示分别输入。有效用户偏好更新后即时应用，不重建地图或改变共享视野。实施方案见 `research/radar-settings-plan.md`，用户已回复“开始实现吧”。
- 2026-09-12 背景模糊校准：用户确认总体效果满意，但模糊应达到看不清背景场景细节的程度。以实际渲染校准 CSS 强度，不把 Source2 的高斯参数按数值直接照搬；只处理背景层，地图和玩家图标保持清楚。
- 2026-09-11 用户明确要求复用本任务，先应用完整的 SCP-079 房间 SVG，替换已实现的统一方块/连接条房间示意。采用这套房间素材与映射依据，覆盖办公区和重收容区，并保持玩家世界坐标对齐。
- 接收 versioned `minimap.init`，按 seed、game/template version、generator version 和 coordinate system 解析 SCP:SL 真实地图。
- 首版固定兼容 SCP:SL `14.2.7`、`@scpsl-tools/map-seed@1.0.0`（需锁定依赖/commit）；不支持版本必须拒绝而不是猜测。
- 地图显示范围仅为 `Entrance`（办公区）和 `HeavyContainment`（重收容区）。不显示轻收容区、地表及其他区域，缩放全图时也不扩展这个范围。
- 接收服务端已过滤的完整位置帧：自己、队友、自己视线敌人、队友视线敌人；省略 marker 即代表当前不可见。
- 本人死亡后仍显示本方队友及其视野内服务端授权的敌人；不得因本人死亡关闭雷达，也不得将共享视野缩小为仅某一名被观战队友的视野。死亡不能提升为敌方全图权限。
- 绘制房间/区域/连线/玩家朝向和可见性样式，按统一 Unity XZ 坐标转换；不接收全量玩家数据，不把 CSS 过滤当安全边界。
- 普通视图自动跟随服务端提供的当前视点及所在区域。空间视点与队伍可见性权限分离，切换观战对象不得改变队伍共享可见集合。
- 无有效视点时显示两区域固定方向概览，并继续显示新鲜授权 marker；不能用历史死亡位置冒充当前视点，不能因此隐藏队伍共享视野。
- 2026-09-11 最新用户决定：移除地图内部中文房间名称，不再提供逐房间标签层。底部按实机样式仅显示当前位置提示，使用显式中文词表，未知名称回退区域，不显示内部英文标识。此前标签固定锚点修复作为历史交付记录保留，不再作为当前标签显示需求。
- 支持固定地图方向与跟随视点朝向旋转两种模式，朝向设置由独立偏好接口输入，无有效偏好时默认固定方向。预留正式主界面设置接入，不在雷达旁增加临时设置弹窗；设置页面的交付不属于本任务。
- 按住计分板期间，在原雷达面板内缩放至能看见办公区与重收容区完整布局，不打开独立大地图，不抢夺焦点，不改变点击穿透模式。计分板关闭后恢复原缩放、视点跟随和方向设置。2026-09-11 实机设置增量允许按“计分板方形／强制方形”偏好切换可视形状；面板锚点保持稳定，HUD 大小由独立偏好控制。
- 计分板联动跟随 SLGO 实际显示状态，兼容游戏内改键及模态界面禁止打开的情况；不能把大小写锁定状态当作按住状态。
- 处理位置帧丢失、sequence 过期、地图重建、实例切换和 stale 状态，更新频率以 sidecar 最终契约为准。
- 位置流过期、非法或连接断开时清除全部动态 marker 和临时全图状态，保留仍能确认适用的底图，明确显示失联/过期/不兼容状态；不显示冻结的队友实时位置或最后已知敌人位置。
- 小地图 payload 不兼容应仅使小地图不可用，不影响后续合法 HUD、商店和聊天数据；认证或全局协议错误仍按统一连接边界处理。
- 采用手工 React 实现并遵守 `.trellis/spec/frontend/cs2-visual-replication.md`：以固定分辨率 CS2 截图为视觉结果基准，`layout/mapoverview.xml`、`layout/hud/hudradar.xml`、相应 CSS 和 `images/hud/radar/*` 为结构、尺寸和资源证据。地图基底、marker、朝向、区域和中文标签分别建立 source map。

- [x] 地图解析、坐标转换、可见性边界和 stale/reconnect 有单元/fixture 测试，渲染有浏览器 smoke 检查。

## Out of Scope

- 门的开关、锁定、破坏状态与交互。
- 独立大地图、自由平移地图工具、轻收容区与地表等其他区域。
- 正式主界面、应用启动流程、设置页面及覆盖层启停管理；由 `09-07-app-home-settings` 独立规划，与本任务通过偏好和覆盖层生命周期接口衔接。
- 无队伍旁观者或管理员的全知视野、客户端敌人可见性计算、闭源插件和 sidecar 实现。

## Technical Notes and Delivery Limits

- 朝向、viewer/视点、地图身份、计分板状态和失败传播合同已写入 `design.md` 与 `research/protocol-and-state.md`。本任务交付客户端、公开契约与 mock 验收；真实插件和 sidecar 的身份/房间映射、共享视野、能力协商和计分板桥接是生产联调依赖，不能以 mock 通过宣称已经接通。
- 生成器浏览器适配已完成 16 组全输出等价探测，证据在 `research/generator-and-rendering.md`；实际浏览器渲染性能与同版本房间资产仍须在实施阶段验证。
- 首轮没有 CS2 实机雷达参考。用户于2026-09-11提供裁剪实机图与对应自定义设置，现保存在 `research/reference-cs2/`；用于视觉层次及对应配置对照，缺少完整游戏分辨率时不能据此声明绝对像素一致。
- 主界面尚未交付时，两种方向模式先由开发 fixture/偏好接口验证，不把临时调试入口作为正式设置交付。
