# 小地图指挥官卡（持有者 + 掉落位置）与己方箭头白色

## Goal

在小地图上表达 SLGO 的指挥官卡（`KeycardMTFCaptain`，CS2 C4 的对应物）：谁拿着卡、卡掉在哪里；同时把己方标记上的朝向箭头恢复为白色。规则对齐 CS2 雷达对 C4 携带者 / 掉落 C4 的处理。来源：用户 2026-10-01 请求。

## Requirements

### R1 持卡人（CS2 C4 携带者）
- 持有指挥官卡的玩家，其小地图标记上显示指挥官卡图标，画在圆点上方（用户 2026-10-01 反馈：画在下面奇怪）。
- 己方（本人、队友）和对该队有观察授权的观察者始终看得到；敌方（SCP 方）在发现持卡人时也看得到（用户 2026-10-01 决定照 CS2）。
- 只有存活（live）标记可以带持卡标志；最后已知 `?` 和死亡 `X` 不带。
- 卡片颜色跟随持有人标识色（队友槽位色，敌人红色）；敌方视角里的卡（含掉落 / 安放 / 淡出中）为红色（用户 2026-10-01 在 CS2 实机确认）。

### R2 掉落 / 失去视野的指挥官卡
- 卡以掉落物形式存在于 EZ / HCZ 时，小地图在掉落位置显示指挥官卡图标，外加 CS2 掉落 C4 式的红色脉冲圈。
- NTF 方 viewer（含已死亡的 NTF 方玩家）与对 NTF 队有观察授权的观察者：始终可见。
- SCP 方 viewer：本 tick 有任一 SCP 队员（含 SCP-079 摄像头）对掉落点有视野时可见。
- 本队失去对卡的视野后（掉落卡或持卡人），图标停在最后看到的位置，8 秒内线性淡出后消失（CS2 `BOMB_FADE_TIME`）；期间再次看到即恢复。
- 卡在 LCZ / 地表等不支持区域，或卡不存在时不显示实时位置。

### R2b 启动发电机后的指挥官卡（CS2 已安放炸弹）
- NTF 用指挥官卡启动发电机后（卡从库存移除，发电机进入倒计时），雷达上的卡固定在该发电机的位置，外加 CS2 已安放炸弹的红色脉冲圈（用户 2026-10-01 请求）。
- 可见性与掉落卡相同：NTF 方与 NTF 观察者始终可见；SCP 方仅在有队员看到该发电机时可见，失去视野后 8 秒淡出。

### R3 己方朝向箭头为白色
- 己方标记（本人、队友，含槽位色）的朝向箭头显示为原图白色（黑色描边），不再被槽位色染色；箭头露出约 4px 并精确居中在圆点轴线上（用户反馈：8px 太细、11px 太大且歪）。

### R4 协议
- 以上信息由 SLGO 插件权威计算，经 slgo-backend 转发，slui 只校验和渲染；客户端不推断持卡或视野。
- 字段变更需要协议版本递增，不能让旧客户端收到无法解析的帧。

## Acceptance Criteria

- [x] `@slgo/protocol` minimap payload v4：合法示例通过（含敌方持卡、last-known 物品）；非法关系被拒绝（非 live 标记带持卡、多于一个持卡人、持卡与物品并存、物品位姿非法、live 物品非掉落 / 年龄非 0、last-known 物品年龄 ≥ 8000）。
- [x] slui 渲染：持卡人标记上方显示卡图标（含被发现的敌人）；掉落卡显示图标与脉冲圈；已安放的卡固定在发电机并显示 `#D10000` 小圈；last-known 物品按本地时钟 8 秒淡出；超出雷达范围时贴边显示；mock `?minimapKeycard=carried|dropped|planted|lost` 可见各状态。
- [x] 己方朝向箭头计算 `filter` 为 `none`、9×9 且轴线与圆点中心对齐（浏览器验证）。
- [x] SLGO 插件：持卡与物品的可见性 / 淡出矩阵单测；发送前自检与 v4 解析器等价。
- [x] slgo-backend：IPC v1 minimap 夹具升级到 v4，契约测试通过（`tls.test.ts` 偶发超时与本任务无关）。
- [x] 各仓库现有测试 / smoke 全绿；spec 与 SOURCE-MAP 更新。

## Out of Scope

- 卡在上下层的 above / below 指示（CS2 `map_bomb_above/below`）。
- 顶部 HUD 持卡图标改接真实数据（目前仍是 mock `hasC4`），另开任务。
