# SLUI 主界面与设置

## Goal

应用启动后进入一个正式的主界面，而不是直接变成透明覆盖层。玩家在主界面里查看自己能否使用覆盖层（Steam 账号、游戏、服务器连接），手动启用或停用覆盖层，并调整雷达的 11 项设置；设置即时生效、保存在本机，重启后保留。关闭主窗口时应用退到系统托盘继续运行。

## Background

- 本任务是 `08-25-slui-mvp` 的子任务，2026-09-07 建立，按用户要求排在 `08-25-minimap` 之后实施。
- 小地图已于 2026-09-12 交付 11 项雷达偏好接口：`src/features/minimap/preferences.ts` 导出 `RadarPreferences`、`DEFAULT_RADAR_PREFERENCES`、`RADAR_NUMERIC_RANGES`、`normalizeRadarPreferences()`；覆盖层通过 `useMinimapFeature({preferences, controls, renderCapabilities})` 接入。`controls.alternateZoomActive` 是动作状态，`renderCapabilities.pageBackdrop` 是呈现能力，二者都不是用户偏好，不保存。预览与验收说明见 `../08-25-minimap/research/radar-settings-verification.md`。
- 2026-09-25 代码现状：
  - `src-tauri/tauri.conf.json` 只定义一个 `main` 窗口：`transparent`、`decorations:false`、`alwaysOnTop`、`skipTaskbar`、`focus:false`。应用启动即是覆盖层，没有主界面。
  - `src-tauri/src/lib.rs` 把该窗口硬编码为覆盖层：`setup` 设为被动输入；`start_foreground_tracking` 每 100ms 用 `SWP_SHOWWINDOW` 把它对齐到前台窗口；键盘钩子和游戏前台事件都 `emit_to("main", ...)`。`capabilities/default.json` 只授予 `core:default`、`opener:default`，未安装托盘、存储或窗口管理插件。
  - `src/App.tsx` 是覆盖层组合（HUD、雷达、商店）。雷达偏好在调试构建里来自 `readMinimapPreviewOptions()` 读 URL，正式构建一直用默认值，没有持久化。
  - 现有“游戏前台”信号（`get_game_foreground` / `slgo-game-foreground`）只表示 SCPSL 窗口有无焦点，不能回答“游戏是否在运行”。
  - 连接状态来自 `src/app/useClientSession.ts`，状态结构为 `ClientSessionState { status, identity, detail, attempt }`。

## Decisions (user, 2026-09-25)

- D1 视觉：普通桌面应用风格，深色系。不复刻 CS2 设置页，也不适用 `.trellis/spec/frontend/cs2-visual-replication.md` 的截图验收门槛。
- D2 窗口生命周期：关闭主窗口只隐藏主窗口，覆盖层保持当前启停状态继续运行；新增系统托盘图标，用于重新打开主界面、启停覆盖层和退出应用。
- D3 主界面内容：单页三块——顶部状态栏（Steam 账号、游戏是否运行、服务器连接）；中部覆盖层启用/停用开关，并说明覆盖层只在商店等界面打开时接管鼠标；下部设置区，含“雷达”一组 11 项与“快捷键”（商店热键，2026-09-26 新增）。
- D5 单实例（2026-09-25 追加）：同一时间只允许运行一个 SLUI。再次启动时新进程直接退出，已运行的实例像普通软件一样把主界面调到前台（从托盘或最小化恢复）并闪烁任务栏按钮提示。
- D4 设置生效：修改即时应用到覆盖层并自动保存到本机，提供“恢复默认”按钮；不设保存/取消按钮。

## Requirements

- R1 启动：应用启动显示主窗口；覆盖层窗口存在但默认停用（隐藏、不接收输入、不跟随前台窗口）。每次启动都从停用开始，不记忆上次的启停状态，保证覆盖层不会未经用户操作接管显示或输入。
- R2 覆盖层启停：主界面开关与托盘菜单都能启用/停用覆盖层，两处状态始终一致。停用时隐藏覆盖层、恢复被动点击穿透、清除交互模式与商店打开状态、停止跟随前台窗口，并且不再响应商店热键 / Y 快捷键；再次启用时从被动模式开始。
- R3 状态栏：显示真实状态，不伪造。
  - Steam：已识别则显示 SteamID（本机读取，仅作展示）；否则显示“未检测到 Steam 登录”。
  - 游戏：按 SCPSL 进程是否在运行显示“运行中 / 未运行”，不依赖游戏窗口是否在前台。
  - 服务器：按 `ClientSessionState.status` 显示已连接 / 连接中 / 未连接 / 未授权 / 版本不兼容 / 数据过期等，失败时可显示 `detail` 并提供“重试”。
  - 主界面可用不代表已获准接收玩家数据；身份授权与 sidecar 判断仍由现有会话逻辑负责。
- R4 雷达设置：设置区列出 11 项，名称沿用小地图配置合同中的中文名：居中、旋转、地图与背景融合、背景模糊、背景透明度、HUD 大小、地图缩放、切换缩放、计分板方形、强制方形、动态缩放。布尔项为开关；方向为“固定 / 跟随视角”选择；数值项为滑块加数字框，范围、步长与默认值直接取自 `RADAR_NUMERIC_RANGES` / `DEFAULT_RADAR_PREFERENCES`，不在本任务另写一份规则。
- R4a 能力说明：Tauri 透明覆盖层无法采样背后的游戏画面（`renderCapabilities.pageBackdrop` 在原生窗口中为 false，见 `../08-25-minimap/research/radar-settings-plan.md` 第 45–47 行），“背景模糊”在原生覆盖层中不产生效果。设置页该项旁显示一行说明，不隐藏该选项、不谎称已生效。
- R5 即时生效与保存：每次修改立即发送到覆盖层应用，并写入本机配置文件；“恢复默认”一次性恢复 11 项默认值并保存。雷达地图生成、坐标转换、可见性权限、`alternateZoomActive` 与 `pageBackdrop` 不在设置里出现或保存。
- R6 持久化健壮性：启动时读取本机配置并经 `normalizeRadarPreferences()` 规范化；文件缺失、损坏或含越界/未知值时回退到默认或最近合法值，不崩溃；损坏的文件保留备份后重建。
- R7 托盘：托盘图标常驻；左键单击显示并聚焦主窗口；右键菜单含“打开主界面”“启用覆盖层 / 停用覆盖层”（随状态切换）和“退出”。“退出”关闭所有窗口并结束进程。
- R8 主窗口行为：普通有边框窗口，显示在任务栏，可最小化/恢复；点关闭按钮时隐藏到托盘，不退出。主窗口与覆盖层互不抢焦点：启停覆盖层不会把焦点从主窗口移走，覆盖层被动模式下不获得焦点。
- R9 开发预览：浏览器开发模式可通过 URL 分别预览主界面与覆盖层；现有调试 URL 预设（`minimapPreset` 等）继续覆盖覆盖层的偏好，供截图审计使用，不影响正式构建。
- R10 单实例：第二次启动不创建新窗口或新托盘图标；已运行实例显示、还原并尝试聚焦主窗口，同时闪烁其任务栏按钮（Windows 阻止抢前台时至少闪烁可见）。覆盖层启停状态不受影响。

## Acceptance Criteria

- [x] AC1 (R1) 正常启动只出现主窗口；覆盖层不可见、不拦截点击，快捷键无反应，直到用户启用。
- [x] AC2 (R2) 从主界面或托盘启用/停用覆盖层，两处状态同步；停用后没有残留透明窗口、交互模式、商店打开状态、雷达切换缩放按住状态或快捷键响应；反复启停 10 次行为一致。
- [x] AC3 (R3) 无 Steam、未运行游戏、未连接服务器时主界面照常可用，并分别显示对应的未检测/未连接文案；游戏运行但主窗口在前台时仍显示“运行中”；连接失败可点“重试”。
- [x] AC4 (R4, R5) 11 项设置的控件类型、范围和默认值与 `preferences.ts` 一致；在主界面改任一项，覆盖层雷达在 0.5 秒内变化；“恢复默认”恢复全部 11 项。
- [x] AC5 (R5, R6) 修改后重启应用，11 项设置保持；手动写入损坏 JSON 或越界值后启动，应用正常运行、设置回退到合法值、原文件留有备份。
- [x] AC6 (R7, R8) 关闭主窗口后应用仍在托盘，覆盖层状态不变；托盘左键重新打开主窗口；托盘“退出”结束进程且不留窗口；最小化/恢复正常。
- [x] AC7 (R8) 覆盖层被动模式下主窗口可正常输入；商店热键打开商店时进入交互模式、关闭商店后恢复点击穿透；启停覆盖层不抢走主窗口焦点。
- [x] AC9 (R10) 应用运行时（主窗口可见、最小化或隐藏到托盘三种情况）再次双击启动：只剩一个进程、一个托盘图标，主窗口出现在前台或任务栏按钮闪烁。
- [x] AC8 `npm run lint`、`npm test`、`npm run build` 通过；新增偏好存储与覆盖层状态逻辑有 smoke 测试；`npm run tauri:check` 能运行时通过，不能运行时说明原因。Windows 上的托盘、窗口、焦点行为需在 Windows 实机 smoke 验证，容器内结果不能替代。

## Out of Scope

- 小地图房间生成、门状态、独立大地图和新增游戏视野权限。
- 通用启动器、多游戏支持、服务器管理后台。
- 更新器、开机自启动、快捷键改键界面，以及雷达以外的设置类别。
- 记忆覆盖层上次启停状态（与 R1 冲突）。
- CS2 风格复刻与截图对比验收（D1）。
